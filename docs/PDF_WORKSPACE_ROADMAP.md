# SwiftLocal PDF 工作區未來開發計劃

## 一、計劃定位

SwiftLocal 未來將加入一個專用的 **PDF 工作區（PDF Workspace）**，為日常行政、文書及個人使用提供簡潔、本機優先的 PDF 閱讀與處理體驗。

PDF 工作區不以完整取代 Adobe Acrobat、Foxit PDF Editor 等專業軟件為目標，而是集中解決日常最常見的需要：

- 快速開啟及閱讀 PDF
- 填寫一般 PDF 表格
- 加入文字、標記及簽名
- 列印及另存文件
- 關閉文件後立即釋放檔案
- 所有文件均在本機處理
- 遇到特殊銀行或政府表格時，清楚提示改用 Adobe Acrobat

此功能將先作為 SwiftLocal 的獨立模組開發。產品上屬於 SwiftLocal，架構上保持可分拆性，日後可按實際使用情況評估是否推出獨立的 SwiftPDF。

---

## 二、核心目標

### 1. 改善日常 PDF 使用體驗

提供比 Adobe Acrobat 更簡潔及輕量的閱讀介面，避免不必要的背景程序、登入要求、雲端推廣及功能干擾。

### 2. 支援一般行政文件處理

滿足公司及個人常見用途，包括：

- 填寫政府及銀行的一般 AcroForm 表格
- 輸入中文及英文文字
- 剔選方格及單選項目
- 加入日期、簽名圖片及簡單標記
- 儲存、另存及列印已填寫文件

### 3. 避免長時間鎖定檔案

PDF 載入後應盡快釋放原始檔案控制權，令使用者即使仍在閱讀文件，也可在檔案總管內移動、複製或重新命名原始檔案。

### 4. 保持本機優先

PDF 內容不應自動上傳至任何伺服器。閱讀、填表、簽名及一般處理均在本機完成。

### 5. 建立清晰的相容性邊界

程式應辨識一般 AcroForm、XFA 動態表格及包含數碼簽署的文件。

遇到不適合由 SwiftLocal 處理的文件時，應顯示清楚提示，並提供「使用 Adobe Acrobat 開啟」的選項。

## 三、產品形式

PDF 工作區將採用「一個程式、兩種入口」的方式。

### SwiftLocal 工具箱入口

使用者可從 SwiftLocal 主畫面進入 PDF 工作區，並繼續使用現有功能：

- PDF 合併
- PDF 分割
- 抽取頁面
- 旋轉頁面
- 浮水印
- 頁碼
- PDF 轉圖片
- 文字抽取
- OCR
- 加密及解密

### PDF 直接開啟入口

Windows 使用者可將 SwiftLocal 設為 PDF 的預設開啟程式。

雙擊 PDF 後，程式應直接進入 PDF 工作區，而不是先顯示 SwiftLocal 工具箱首頁。

PDF 工作區的介面應接近一般 PDF Reader：

```text
頁面縮圖｜PDF 文件內容｜閱讀及編輯工具列
```

## 四、功能範圍

### 第一階段：PDF 閱讀核心

建立可穩定使用的 PDF 閱讀器。

功能包括：

- 開啟本機 PDF
- 拖放 PDF 至程式
- 頁面縮圖

- 適合寬度
- 順時針及逆時針旋轉檢視
- 全文搜尋
- 複製可選取文字
- 列印
- 最近開啟文件
- 關閉文件
- 關閉後釋放檔案
- 基本密碼保護文件提示

第一階段以穩定、快速及不鎖檔為主要驗收目標。

### 第二階段：一般表格填寫

支援常見 AcroForm 表格。

功能包括：

- 文字欄位輸入
- 多行文字欄位
- 核取方塊
- 單選按鈕
- 下拉選單
- 日期欄位
- 表格欄位切換
- 儲存表格內容
- 另存副本
- 關閉前提示未儲存變更
- 重新開啟後確認填寫內容仍然存在

此階段應優先測試：

- 中文輸入
- 繁體中文字型
- 政府表格
- 銀行表格
- 僱傭及強積金文件
- 列印後文字位置
- 不同 PDF 閱讀器重新開啟後的顯示結果

### 第三階段：基本註解及簽名

加入日常行政工作最常用的簡單編輯功能。

功能包括：

- 在指定位置加入文字
- 加入剔號
- 加入交叉
- 加入圓圈
- 螢光筆
- 底線
- 刪除線
- 矩形框
- 箭嘴
- 自由手寫
- 加入簽名圖片
- 儲存常用簽名
- 加入日期印章
- 復原及重做
- 刪除已加入的標記

簽名圖片應只儲存在使用者本機，並提供移除功能。

### 第四階段：頁面整理整合

將 SwiftLocal 現有的 PDF 工具整合至工作區。

功能包括：

- 刪除頁面
- 重新排列頁面
- 抽取頁面

- 只改變目前檢視
- 永久修改 PDF 文件

### 第五階段：檔案關聯及多文件操作

改善作為日常 PDF Reader 的完整體驗。

功能包括：

- Windows PDF 檔案關聯
- 雙擊 PDF 直接開啟工作區

- 最近文件清單
- 從檔案總管拖放多個文件
- 多視窗或單視窗選項
- 快速使用 Adobe Acrobat 開啟
- 快速顯示檔案所在資料夾

## 五、特殊表格及相容性策略

SwiftLocal 不承諾完整支援所有 PDF 表格。

### 一般 AcroForm

由 SwiftLocal 直接提供填寫及儲存功能。

### XFA 動態表格

若偵測到 XFA，顯示提示：

> 此文件使用特殊動態表格。部分欄位、自動計算、頁面變化或提交功能未必能正確運作，建議使用 Adobe Acrobat Reader 開啟。

提供以下選項：

- 繼續以唯讀方式開啟
- 嘗試開啟
- 使用 Adobe Acrobat 開啟
- 取消

### 數碼證書及特殊簽署

若文件包含數碼簽署欄位、憑證驗證或受保護的提交程序，應提示使用 Adobe Acrobat 或指定官方軟件。

SwiftLocal 初期只支援加入手寫簽名或簽名圖片，不把此類簽名描述為具備法律認證的數碼簽署。

## 六、技術架構

PDF 工作區應作為相對獨立的模組開發。

建議結構：

```text
frontend/
  app/
  pdf-workspace/

shared/
  settings/
  file-dialogs/
  error-handling/
  recent-files/

pdf-core/
  viewer/
  forms/
  annotations/
  save/
  print/
  compatibility/

desktop/
  main.js
  preload.js
  pdf-window.js
  file-associations.js
```

### 核心元件

- PDF.js：PDF 顯示、頁面渲染、搜尋及文字層
- pdf-lib：一般表格、文字、圖片及 PDF 儲存
- Electron：桌面視窗、檔案關聯、列印及本機檔案操作
- SwiftLocal 現有後端：OCR、加密、解密及需要外部工具的處理

### 模組化原則

PDF 工作區不應直接依賴 SwiftLocal 主畫面的具體 UI。

共用的設定、錯誤處理及檔案工具可以抽至 shared 模組。

此設計令 PDF 工作區未來可：

- 留在 SwiftLocal
- 作為 SwiftLocal Lite 的功能
- 分拆成獨立 SwiftPDF
- 與其他 SwiftLocal 工具共用核心程式碼

## 七、檔案鎖定處理原則

為避免重現 Adobe 關閉後仍佔用文件的問題，程式應採用以下方式：

1. 開啟文件時讀取所需資料。
2. 完成載入後立即關閉原始檔案控制權。
3. 閱讀期間主要使用記憶體中的資料。
4. 儲存時才重新短暫開啟輸出檔案。
5. 預設提供「另存新檔」。
6. 直接儲存時先寫入暫存檔。
7. 寫入成功後才安全取代原檔。
8. 關閉文件時清除快取及相關物件。
9. 程式結束時不保留背景 PDF 程序。

若原始文件在閱讀期間被移動、改名或刪除，程式應提示使用者改用「另存新檔」。

測試類型包括：

- 純文字 PDF
- 掃描 PDF
- 大型 PDF
- 中文 PDF

## 十一、主要風險

### 表格相容性

不同 PDF 產生工具的欄位實作可能不一致，因此需建立清楚的支援範圍及警告機制。

### 中文字型

加入文字或填寫欄位時，需確認繁體中文字型可正確嵌入，避免在其他電腦上變成空白或亂碼。

### 儲存安全

直接修改原檔存在資料損壞風險，因此應使用暫存檔及安全取代流程。

### 大型文件效能

PDF 不應一次渲染所有頁面。應採用按需載入、縮圖快取及可見頁面渲染。

### 使用者誤解

程式需要清楚區分：

- 手寫簽名圖片
- PDF 數碼簽署
- 政府或銀行指定的電子簽署

### 功能膨脹

PDF 工作區應優先完成閱讀、普通填表及日常標記，不在早期追求完整 PDF 編輯器功能。

---

## 十二、是否分拆成獨立 SwiftPDF

初期維持在 SwiftLocal 內開發。

當以下情況持續出現時，再考慮分拆：

- 多數使用者只使用 PDF 工作區
- PDF 功能更新頻率高於其他 SwiftLocal 功能
- 主程式體積或啟動速度受到明顯影響
- 使用者希望只安裝 PDF Reader
- PDF 工作區已有大量獨立設定
- PDF 使用者不需要 OCR、影音或文件轉換工具

若日後分拆，應保留共用核心：

```text
SwiftLocal
SwiftPDF
    ↓
共用 pdf-core
```

避免複製及分叉兩套 PDF 程式碼。

---

## 十三、最終方向

SwiftLocal PDF 工作區的核心價值是：

> 提供一個本機、簡潔、可靠、不鎖檔的日常 PDF 閱讀及填表工具。

它不需要在第一天取代 Adobe，也不需要支援所有複雜 PDF 標準。

首要任務是把最常用的部分做好：

- 開得快
- 看得清楚
- 中文正常
- 普通表格填得到
- 簽名及標記方便
- 儲存可靠
- 關閉後不佔用檔案
- 特殊文件懂得提醒使用 Adobe

產品上，PDF 工作區屬於 SwiftLocal；架構上，它應保持獨立；日後再根據實際使用數據，決定是否發展成獨立的 SwiftPDF。
