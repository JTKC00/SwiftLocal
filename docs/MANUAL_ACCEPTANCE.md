# SwiftLocal 集中人工驗收清單

本文件供功能完成後一次過做人工驗收。日常開發先以自動測試與 release smoke 把關，不要求每一階段重複手動點選。

## 驗收原則

- 建議先在 Windows 桌面版完成主驗收，再於瀏覽器模式與 macOS 做平台差異抽查。
- 每個案例使用可公開的測試檔；不要用含敏感資料的真實文件。
- 除非案例特別要求缺少工具，桌面版應能偵測 Tesseract、`chi_tra+eng`、FFmpeg、QPDF；Office 正式流程另需 LibreOffice。
- 檔案全程留在裝置；介面不可暗示上傳、登入或雲端處理。
- 每個失敗項目記錄平台、版本、輸入類型、操作步驟、實際結果與診斷內容。

## 1. 啟動與資訊架構

- [ ] 首頁定位是「本機優先的辦公文件與媒體處理工作台」，沒有雲端帳戶或上傳入口。
- [ ] 側欄依序清楚呈現開始、五大核心工作區、自動化、其他工具及系統。
- [ ] 首頁、搜尋、常用預設與最近任務都能直接進入正確工作區及模式。
- [ ] PDF、OCR、Office、圖片、影音入口的名稱及說明以使用目的為主，不要求先理解引擎名稱。
- [ ] ZIP、Hash、批量改名、文字／資料及開發工具仍可用，但不搶佔核心入口。
- [ ] 重新啟動後，主題、常用預設及其他已承諾保存的偏好仍在。

## 2. 能力狀態與隱私文案

- [ ] OCR 首頁正確顯示引擎及繁中、英文語言包的可用狀態。
- [ ] Office 首頁區分 LibreOffice 正式流程與 PDF → Word 相容流程的狀態。
- [ ] 引擎缺少、語言包缺少及瀏覽器離線服務狀態都有明確修復入口，功能入口不會無故消失。
- [ ] 修復入口會到「狀態與設定」，並聚焦相關工具說明。
- [ ] 桌面與瀏覽器模式的隱私提示符合實際處理位置；不把本機磁碟處理誤寫成純頁面記憶體處理。

## 3. PDF 工作區

### 閱讀與填表

- [ ] 從首頁、側欄、搜尋及檔案關聯開啟 PDF，都進入閱讀與填表的合理起點。
- [ ] 開啟多份 PDF、切換分頁、縮放、搜尋文字、頁面跳轉及列印正常。
- [ ] 表單欄位可輸入文字、日期及勾選；簽名可加入、移動及刪除。
- [ ] 儲存副本不覆蓋原檔；關閉未儲存文件前有清楚提示。

### 頁面整理

- [ ] 合併、分割、抽取、刪除、重排及旋轉頁面結果與預覽一致。
- [ ] 多檔選擇、拖放順序及輸出命名清楚，重名時不覆蓋既有檔案。

### 轉換與 OCR

- [ ] PDF 轉圖片、圖片轉 PDF、PDF 轉文字及可搜尋 PDF 可完成並開啟輸出。
- [ ] 一般 PDF → Word 使用預設正式／相容路徑，輸出可由常用 Office 軟件開啟。
- [ ] 掃描 PDF → Word 自動展開進階設定並啟用 OCR；預設語言是 `chi_tra+eng`。
- [ ] PDF → Excel／PowerPoint 明確標示實驗性，不承諾百分百還原版面。
- [ ] 技術引擎、語言代碼與 OCR fallback 收在進階設定，但可被鍵盤操作。

### 保護與壓縮

- [ ] 壓縮、加密、解密及浮水印完成；密碼不出現在任務歷史或診斷報告。
- [ ] 錯誤密碼、受損 PDF 及不支援檔案會顯示可理解的錯誤與下一步。

## 4. OCR 工作區

- [ ] 單張與多張圖片可輸出文字，繁中及英文辨識結果可接受。
- [ ] 掃描 PDF 可輸出純文字、可搜尋 PDF 及 Word，頁數與語言設定有效。
- [ ] 「批量圖片 OCR」及「批量 PDF OCR」分別進入正確既有表單，並允許多檔。
- [ ] 批量工作的成功、部分失敗、取消及輸出檔案對應關係清楚。
- [ ] 移除一個測試語言包或模擬缺少引擎時，狀態與修復提示正確；恢復後可重新偵測。

## 5. Office 工作區

- [ ] DOCX、XLSX、PPTX 轉 PDF 正常，批量轉換保留每個來源的結果。
- [ ] PDF → DOCX 的預設、保留版面及直接相容模式都能完成或提供可操作錯誤。
- [ ] 掃描 PDF → Word 從 Office 首頁進入時，模式、輸出格式、OCR 與多檔選項已正確預設。
- [ ] 批量 Office 入口沿用 Office → PDF 任務；沒有產生功能重複或不同結果的另一套流程。
- [ ] LibreOffice 不可用時，正式流程清楚標示不可用；可用的相容 fallback 不被錯誤停用。

## 6. 圖片與影音工作區

- [ ] 圖片轉格式、壓縮、調整尺寸、旋轉／翻轉及浮水印可完成單檔與批量工作。
- [ ] 圖片用途預設會帶入合理參數，而且使用者仍可修改。
- [ ] 影片壓縮、轉檔、剪取、擷取音訊及 GIF 可完成，輸出格式與用途說明一致。
- [ ] 影音用途預設、品質／大小估算及進階 FFmpeg 選項不互相覆蓋。
- [ ] 不支援 codec、損壞媒體與磁碟空間不足會提供可理解的診斷。

## 7. 任務、預設與工作流程

- [ ] 多個任務排隊時，等待中、執行中、取消中、完成及失敗狀態中文一致。
- [ ] 等待中及執行中任務都可取消；取消中不會被誤報為已完成。
- [ ] 失敗任務可重試；多步工作流程可從失敗步驟繼續，不重做已成功且仍有效的輸出。
- [ ] 重開 app 後，佇列及歷史按設計恢復；中斷中的任務不會永久卡住。
- [ ] 可開啟輸出檔及輸出資料夾；清理歷史或暫存不會刪除使用者已保存的輸出。
- [ ] 常用預設能建立、套用、重新命名及刪除；跨工作區不會套入不相容欄位。
- [ ] 工作流程會正確傳遞上一步輸出，部分失敗時可看出失敗檔案及步驟。

## 8. 其他工具與相容性

- [ ] ZIP、批量改名、Hash、檔案分片、文字整理、繁簡、CSV、QR Code、JSON、XML、Base64、URL 及 HTML 工具仍可進入並完成一個基本案例。
- [ ] 舊書籤、舊預設或舊任務引用既有 panel id／job type 時仍能合理開啟或顯示相容提示。
- [ ] 搜尋能找到核心功能及其他工具，同名結果可辨識所屬工作區。

## 9. 瀏覽器、視窗與無障礙抽查

- [ ] 瀏覽器模式在本機服務連線、未連線及重新連線時，狀態和可用功能同步更新。
- [ ] 桌面大視窗、窄視窗與常見瀏覽器寬度沒有遮擋主要按鈕、橫向溢出或不可達內容。
- [ ] 只用鍵盤可進入側欄、工作區分段、進階設定、表單及任務操作，焦點清楚可見。
- [ ] 狀態不只靠顏色表達；按鈕、欄位、展開區及錯誤訊息有可理解名稱。
- [ ] 中英文檔名、空格、長路徑及重名輸出可處理。

## 10. 安裝包與最終放行

- [ ] 一般版及 Full 版安裝、啟動、升級與移除符合預期，產物版本和檔名正確。
- [ ] 全新 Windows 使用者環境不依賴開發機 PATH；Full 版能找到內建工具。
- [ ] macOS 包可啟動，簽章／公證及權限提示符合發佈設定。
- [ ] `npm run smoke`、`npm run check:pack`、`npm run verify:win:dir`、`npm run smoke:packaged-ui` 及 Full 版的 `npm run check:pack:full` 全部通過。
- [ ] 沒有阻斷核心流程的錯誤、資料遺失、原檔覆蓋或隱私文案錯誤後，才標記發佈候選版本通過。

## 最後執行：發佈收尾

Phase 1–5 的功能、產品定位與資訊架構已完成。以下工作保留到準備正式發佈時，連同本文件的人工驗收一次過執行：

- [ ] 鎖定要驗收的版本與 commit；收尾期間只納入阻斷發佈的修正。
- [ ] 以該 commit 建立最新 Windows 一般版及 Full 版：執行 `npm run pack:win` 與 `npm run pack:win:full`，取得 portable 及 installer。
- [ ] 執行 `npm run verify:win:artifacts`，並確認一般版與 Full 版的檔名、版本、大小、`app.asar` 及內建工具正確。
- [ ] 完成 Windows 程式碼簽章，抽查 SmartScreen、全新安裝、升級、移除及無開發環境 PATH 的啟動流程。
- [ ] 在 macOS 建立一般版及 Full 版，完成簽章、公證、Gatekeeper 與檔案／資料夾權限驗證。
- [ ] 由本文件第 1 節開始，一次過完成所有人工驗收，並在「驗收記錄」填寫環境、結果及未通過案例。
- [ ] 修正驗收問題後，重跑受影響案例及完整發佈檢查；所有阻斷問題清零後才標記發佈候選版本通過。
